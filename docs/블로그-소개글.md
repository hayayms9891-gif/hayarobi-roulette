# 명절 용돈 룰렛을 HTML 파일 하나로 만들었습니다

명절에 아이들 용돈을 나눠주다 보면 매번 비슷한 고민이 생깁니다. 얼마를 줘야 할지, 형제끼리 차이를 어떻게 설명할지 같은 것들입니다. 그래서 **운에 맡기는 룰렛**을 만들어 봤습니다.

결과물은 HTML 파일 하나입니다. 서버도, 데이터베이스도, 자바스크립트 라이브러리도 쓰지 않았습니다. 이 글에서는 만들면서 내린 몇 가지 결정과, 그 과정에서 확인한 것들을 정리합니다.

- 게임: https://hayayms9891-gif.github.io/hayarobi-roulette/
- 코드: https://github.com/hayayms9891-gif/hayarobi-roulette

---

## 무엇을 만들었나

링크를 열면 12칸짜리 룰렛이 나옵니다. 이름을 적고 버튼을 누르면 약 5초간 돌아가고, 멈춘 칸의 금액이 나옵니다. 그 화면을 용돈 주는 어른께 보여주면 현금을 받는 구조입니다.

| 항목 | 값 |
|---|---|
| 칸 구성 | 꽝 · 1천 · 5천 · 1만 · 2만 · 5만 각 2칸 |
| 1인당 기댓값 | 8,000원 |
| 파일 | `index.html` 한 개 (38KB) |
| 외부 의존성 | 구글 폰트만 |
| 배포 | GitHub Pages (무료) |

설날과 추석 테마를 전환할 수 있고, 휴대폰 세로 화면에 맞춰져 있습니다.

## 확률을 "칸 넓이"와 일치시키기

칸마다 당첨 확률이 다른 룰렛을 만들 때, 보통은 가중치 배열을 따로 둡니다. 그런데 이 방식에는 함정이 있습니다. **화면에 그려진 칸 크기와 실제 확률이 따로 놀 수 있다**는 점입니다.

좁아 보이는 칸이 자주 나오거나 그 반대가 되면, 게임을 하는 사람은 뭔가 이상하다고 느낍니다. 눈으로 보는 것과 결과가 어긋나기 때문입니다.

그래서 칸 번호를 뽑는 대신 **원판 위의 각도**를 뽑았습니다.

```js
function pickSlot(){
  const a = random01() * 360;          // 0~360도에서 균등하게
  for (const s of layout)
    if (a >= s.start && a < s.end) return s.index;
}
```

이렇게 하면 확률이 칸 넓이와 저절로 같아집니다. 관리해야 할 가중치 표가 사라지고, 칸 크기만 바꾸면 확률이 따라옵니다.

부수 효과도 있었습니다. `crypto.getRandomValues()`가 주는 0~2³²−1 값을 칸 개수로 나눈 나머지를 쓰면 앞쪽 번호가 아주 미세하게 더 자주 나오는데(모듈로 편향), 나눗셈만 쓰니 이 문제가 애초에 생기지 않습니다.

실제로 200만 번 돌려 확인한 결과, 실측 기댓값 8,006원으로 이론값 8,000원과 일치했고 바늘 위치와 표시 금액이 어긋난 경우는 없었습니다.

## "아슬아슬하게 멈추는" 연출을 만들지 않은 이유

룰렛의 재미는 마지막 순간에 있습니다. 처음에는 이걸 3단계로 구현했습니다. 한 칸 지나친 곳까지 굴리고, 0.38초 완전히 멈추고, 다시 출발해 되돌아오는 방식입니다.

결과는 어색했습니다. 속도가 0이 됐다가 다시 붙으니 **누가 뒤에서 원판을 미는 것처럼** 보였습니다.

해결책은 연출을 더 다듬는 게 아니라 **멈출 위치를 옮기는 것**이었습니다. 원판을 R도 돌리면 바늘이 가리키는 각도는 `(360 − R) mod 360`이므로, 바늘은 칸의 한쪽에서 들어와 반대쪽으로 빠져나갑니다. 멈출 자리를 "칸에 막 들어선 지점"으로 잡으면, 감속이 끝나갈 무렵 남은 각도가 몇 도뿐이라 경계선을 저절로 천천히 넘습니다.

```js
const settleIn = Math.min(seg.span * 0.45, 4 + Math.random() * 4);
const target   = seg.end - settleIn;   // 칸에 막 들어선 지점
```

감속 곡선은 `easeOutQuart` 하나만 씁니다. 마지막 1.1초 동안 4도 남짓만 움직이며 멈추고, 멈췄다 다시 출발하는 구간이 없으니 이어지는 티가 나지 않습니다.

## 효과음을 음원 파일 없이

명절에는 시골집처럼 네트워크가 느린 환경도 많습니다. mp3를 받아오면 첫 터치에 소리가 안 나는 일이 생깁니다.

그래서 Web Audio API로 파형을 직접 만들었습니다. 게임의 모든 효과음이 이 함수 하나에서 나옵니다.

```js
const tick    = () => tone(1180, 0.033, 'square', 0.07);
const fanfare = () => [523.25, 659.25, 783.99, 1046.5]   // 도미솔도
                     .forEach((f, i) => tone(f, 0.33, 'triangle', 0.2, i * 0.1));
```

룰렛이 돌아가는 "따르륵" 소리는 타이머가 아니라 **매 프레임 바늘이 가리키는 칸이 바뀌었는지** 확인해서 냅니다. 덕분에 속도에 맞춰 저절로 느려지고, 끝에서는 경계를 넘는 순간 한 번만 울립니다.

## 배포는 GitHub Pages로

공개 저장소에 파일을 올리고 설정에서 Pages를 켜면 끝입니다. `git push` 후 약 50초면 반영되고, 주소는 그대로라 링크를 다시 보낼 필요가 없습니다.

GitHub 문서 기준 사용 한도는 다음과 같습니다.

| 항목 | 한도 |
|---|---|
| 사이트 용량 | 1GB |
| 월 전송량 | 100GB (소프트 한도) |
| 시간당 빌드 | 10회 (소프트 한도) |

소프트 한도라서 초과해도 자동으로 요금이 청구되지 않습니다. GitHub이 최적화를 권하거나 서비스 제공을 중단할 수 있다고 안내되어 있습니다. 다만 상업적 용도의 무료 웹호스팅으로 쓰는 것은 허용되지 않으므로, 개인 프로젝트나 문서 용도에 한해 적합합니다.

한 명이 처음 접속할 때 약 361KB를 받습니다. 가족 단위로 쓰는 규모에서는 한도를 신경 쓸 일이 없습니다.

## 하지 않은 것들

만들면서 포기한 기능도 있습니다. 처음 요구사항에는 **이미 나온 금액을 룰렛에서 제거**하는 기능이 있었습니다. 12명이 뽑으면 총액이 정확히 확정되는 방식입니다.

그런데 각자 다른 휴대폰에서 링크를 여는 구조에서는 폰끼리 "누가 무엇을 뽑았는지"를 공유할 방법이 없습니다. 서버나 공유 데이터베이스가 필요해지고, 그러면 "파일 하나, 링크 하나"라는 전제가 깨집니다. 두 요구사항이 동시에 성립하지 않는다는 점을 확인하고 링크 배포 쪽을 남겼습니다.

"한 사람당 한 번"을 브라우저 저장소로 제한하는 기능도 넣었다가 뺐습니다. 시크릿 모드로 열면 우회되기 때문에 완전한 제한이 아니고, 어차피 어른이 옆에서 보고 현금을 주는 상황이라 실익이 없었습니다.

## 세 줄 요약

1. 확률을 가중치 표로 관리하는 대신 **각도를 뽑으면** 화면에 보이는 칸 크기와 실제 확률이 자동으로 일치합니다.
2. 아슬아슬한 멈춤은 별도 연출이 아니라 **멈출 위치 선택**으로 만들 수 있습니다.
3. 정적 HTML 한 파일이면 서버 없이도 충분히 동작하고, GitHub Pages로 무료 배포됩니다.

## 마무리

작업하면서 인상적이었던 점은, 네 가지 문제 중 세 가지가 **무언가를 덜 만들어서** 풀렸다는 것입니다. 확률은 가중치 표를 없애서, 멈춤 연출은 단계를 없애서, 효과음은 음원 파일을 없애서 해결됐습니다.

나머지 하나는 반대였습니다. 휴대폰에서 화면이 안 채워지는 문제를 만났을 때, 눈에 띄게 빠진 `<!DOCTYPE html>`을 보고 바로 원인이라 단정했습니다. 여러 곳을 한꺼번에 고치니 증상이 사라져 맞는 줄 알았습니다.

나중에 두 경우의 높이를 실제로 측정해 보니 아니었습니다. `compatMode`는 갈렸지만 레이아웃 높이는 413px로 같았습니다. 진짜 원인은 `viewport` 메타 태그 누락과 `justify-content` 설정이었습니다. **그럴듯한 원인과 진짜 원인은 다를 수 있고, 그 차이는 재봐야 드러난다**는 걸 다시 확인했습니다.

코드는 전부 공개되어 있고 주석을 달아 두었습니다. 비슷한 것을 만들어 보실 분께 참고가 되면 좋겠습니다.
