## 1. 사용자 흐름

링크를 받은 사람이 겪는 전체 과정.

```mermaid
flowchart TD
    A["카톡으로 링크 받음"] --> B["브라우저에서 열림<br/>(로그인·설치 없음)"]
    B --> C{"명절 테마"}
    C -->|"1~3월"| D1["설날 🧧"]
    C -->|"그 외"| D2["추석 🌕"]
    D1 --> E["이름 입력"]
    D2 --> E
    E --> F["돌리기 버튼"]
    F --> G["당첨 칸 결정<br/>+ 룰렛 5.2초 회전"]
    G --> H["돈봉투 열림<br/>이름 · 금액 · 축하 멘트"]
    H --> I{"다음"}
    I -->|"다음 사람"| E
    I -->|"어른께 보여주기"| J["현금 받기 💰"]

    B -.->|"📱 버튼"| K["QR + 링크"]
    K -.->|"찍기 / 복사"| A
```

> 점선은 게임이 퍼져나가는 경로입니다. 옆 사람은 QR을 찍고, 멀리 있는 사람에겐 링크를 복사해 보냅니다.

## 2. 화면 상태

화면은 세 가지 상태만 오갑니다.

```mermaid
stateDiagram-v2
    [*] --> 시작화면

    시작화면 --> 회전중 : 돌리기
    회전중 --> 결과화면 : 5.2초 뒤
    결과화면 --> 시작화면 : 다음 사람

    시작화면 --> QR화면 : 📱
    QR화면 --> 시작화면 : 닫기

    note right of 회전중
        버튼 잠금
        이름칸 잠금
        하야로비 폴짝
    end note

    note right of 결과화면
        봉투 열림 → 지폐 상승
        폭죽 + 팡파레 + 진동
        (꽝이면 하강음만)
    end note
```

## 3. 돌리기 한 번의 내부 순서

버튼을 누른 뒤 5.2초 동안 코드 안에서 벌어지는 일.

```mermaid
sequenceDiagram
    participant U as 사용자
    participant B as 버튼
    participant P as pickSlot()
    participant S as spinTo()
    participant A as Web Audio
    participant R as 결과화면

    U->>B: 탭
    B->>A: 오디오 깨우기 (첫 터치 필요)
    B->>P: 당첨 칸 요청
    P->>P: 0~360도 균등 난수
    P->>P: 그 각도가 속한 칸 찾기
    P-->>B: 칸 번호

    Note over B: 결과를 먼저 확정<br/>(회전 중 새로고침 대비)

    B->>S: 그 칸으로 회전 시작
    loop 매 프레임 (약 5.2초)
        S->>S: easeOutQuart 감속
        S->>A: 칸이 바뀌면 딸깍
    end
    Note over S: 마지막 1.1초는 4도만 이동<br/>경계선을 기어서 넘음
    S-->>R: 회전 끝
    R->>A: 팡파레 (꽝이면 하강음)
    R->>U: 봉투 열림 + 금액
```

## 4. 당첨 칸을 고르는 방법

가중치 표 없이 확률을 칸 넓이에 맞추는 구조.

```mermaid
flowchart LR
    W["WIDTH<br/>칸별 너비<br/>합 = 12"] --> L["buildLayout()<br/>각 칸의 start·end 각도"]
    L --> D["룰렛 그리기<br/>SVG 부채꼴"]
    L --> P["pickSlot()<br/>각도 뽑아 칸 찾기"]
    P --> Q["당첨 확률"]
    D --> V["보이는 칸 크기"]
    Q -.->|"항상 일치"| V
```

> 그리는 쪽과 뽑는 쪽이 **같은 `layout` 배열**을 씁니다. 그래서 `WIDTH` 한 곳만 고치면 그림과 확률이 함께 움직이고, 둘이 어긋날 수가 없습니다.
